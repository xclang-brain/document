# 5. 移行の進め方

## 5.1 段階的に移行する理由

- 一度に移行すると、開発への影響が大きい
- 各段階で慣れてから次に進める

## 5.2 各段階の内容

| 段階 | 移行するもの |
| --- | --- |
| 1 | コード |
| 2 | GitHub Actions を使った CI |
| 3 | 内部仕様書工程、単体試験工程 |
| 4 | ソフトウェア設計書工程、組み合わせ試験工程 |
| 以降 | V 字の上の工程へ順に |

工程の移行とは、その工程の文書を GitHub で管理し、レビューをプルリクエストで行うことです。

## 5.3 第1段階で開発者にお願いすること

- Git・GitHub の基本操作（pull、ブランチ作成、commit、push、プルリクエスト）を覚える
- 詳しい手順は運用手順書で案内する
